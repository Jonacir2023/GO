* fix: remover FK para tabela obras (não existe — arquitetura per-obra no Supabase)

Migrations SQL estavam referenciando public.obras(id) como chave estrangeira, mas a arquitetura GO usa um Supabase isolado por obra — não existe tabela única de obras. Cada projeto Supabase já É uma obra.

Alterações: - 001_eap_itens.sql: removido FK para obras - 002_planejamento.sql: removido 3x FK para obras (cronogramas, atividades, restrições) - 004_suprimentos.sql: removido 3x FK para obras (requisições, cotações, pedidos) - 003_financeiro_workflows.sql: sem FK, apenas ADD COLUMN a tabelas existentes

Mantidas: - Coluna obra_id em todas as tabelas (organização, namespacing) - FKs internas (cronogramas→eap, atividades→cronogramas, etc.) - Unique (id, obra_id) para garantir isolamento
