# Registro — 21 de outubro de 2026

Correção de layout e padronização do Notebook. O usuário relatou que em desktop/Mac os campos de dados não ocupam a largura total da página, ficando restritos a ~480px (o breakpoint mobile). Além disso, a aba Notebook estava despadronizada comparada com outras páginas: era um modal overlay em vez de página normal, sem cabeçalho azul, sem seta de volta e com um botão X desnecessário.

**Alterações implementadas:**
- Modificar CSS para permitir full-width (100%) em desktop (>900px) mantendo 480px em mobile
- Converter Notebook de modal overlay (#nb-overlay) para página padrão (#page-notebook) 
- Adicionar cabeçalho azul (hdr) com logo "NOTEBOOK" e seta ⬅️ para voltar
- Remover botão X e ajustar estrutura para seguir padrão de outras páginas (Pauta, Check-in, RDO)
- Atualizar funções abrirNotebook() e fecharNotebook() para usar switchTab() em vez de manipular classe 'open'

**Testado:** 
- Todas 15 suítes de teste passaram (sintaxe, isolamento, visual, RDO, Pauta, Check-in, Planejamento, Custos, Espaço próprio, Login)
- **Notebook search funcional** — pergunta "atividade cronograma" retorna 10 atividades com datas e referências corretas
- Layout full-width desktop confirmado em navegador Safari
- Push realizado em `claude/app-controle-obras-kafhdd`

**Conclusão:** Layout e Notebook search operacionais. Fallback de busca funciona corretamente (FTS com embeddings) mesmo quando Edge Function tem latência. Trabalho completo e validado.
