# Registro — 21 de setembro de 2026

Sessão de finalização dos ajustes multi-obra: rate limit para o robô 🤖, cache-busting para Safari, e atualização da URL do Apps Script para nova versão com OAuth scopes.

**Por quê cada mudança:**

1. **Rate limit (20 perguntas/dia):** Defesa em profundidade se o código de acesso vazar. Cada aparelho recebe um deviceId único, e cada pergunta é validada contra um contador diário no Apps Script. O usuário consegue passar num dia normal; em caso de vazamento ou força bruta, a chave da Anthropic fica protegida.

2. **Cache-busting (supabase-config.js):** Safari (iPhone/Mac) é teimoso com cache HTTP — não recarrega .js mesmo com `no-cache`. Query string `?v=<hash>` força reload sem quebrar nada; hash é recalculado sempre que o arquivo muda.

3. **Apps Script redeployed:** URL atualizada para nova versão com OAuth scopes próprios para Anthropic API; permite que o robô consulte dados vivos do Supabase sem intermediação.

**O que foi testado:** 7 suítes pytest, sintaxe (23 blocos), isolamento (14 arquivos). Tudo verde. PR #38 foi mesclado com sucesso em `main` após resolução de merge conflicts.

**Pendente:** 
- Usuário colar `BuildlyBackend.gs` atualizado no editor do Google Apps Script (regra 17 — não é implantado por git)
- Testar robot 🤖 em produção (clicar e fazer uma pergunta) contra Obra 1 e Obra 2
- Comunicar novo URL público ao time (`jonacir2023.github.io/GO/buildly-completo.html`)

**Segunda sessão (21/09 continuação 2):** Adição de 4 novos módulos de gestão integrada (EAP, Planejamento, Financeiro, Suprimentos) baseados na estrutura arquitetural do JC (Gestor Global de Jonacir).

**Por quê:** O GO carecia de visibilidade integrada de planejamento (cronogramas, atividades), estrutura do projeto (EAP/WBS), gestão financeira (medições, aprovações) e suprimentos (requisições, cotações, pedidos). Estes módulos trazem funcionalidades já validadas em produção no JC.

**O que foi criado:**

1. **EAP** (Estrutura Analítica do Projeto)
   - Árvore hierárquica de itens (grupos, pacotes, entregas)
   - CRUD com código, nome, tipo, ativo/inativo
   - Stats: total de itens, pacotes, entregas
   - Tabela: eap_itens (obra_id, pai_id, codigo, nome, tipo, ordem, ativo)

2. **Planejamento** (Cronogramas e atividades)
   - Abas: Cronogramas (baseline/controle/reprogramação), Atividades, Restrições
   - Cronogramas com data de status
   - Atividades linkadas a EAP com % realizado, crítica?
   - Restrições com criticidade (baixa/média/alta/crítica)
   - Tabelas: planejamento_cronogramas, planejamento_atividades, planejamento_restricoes

3. **Financeiro** (Medições, NFs, aprovações)
   - Dashboard com stats: Orçado, Gasto, Faturado, Saldo
   - Abas: Medições, Notas Fiscais, Aprovações Pendentes
   - Integração com tabelas de custos, medições, NFs
   - Workflow de aprovação por medição/NF

4. **Suprimentos** (Requisições até pedidos)
   - Fluxo: Rascunho → Cotação → Aprovação → Pedido Emitido → Cancelada
   - Requisições de compra com EAP, CBS, quantidade, unidade, valor estimado
   - CRUD de requisições, contadores por status
   - Tabela: requisicoes_compra (obra_id, numero, eap_id, cbs_id, status, etc.)

**Implementação:**
- 4 novos HTML com espaço próprio de localStorage (BUILDLY_ESPACO_PROPRIO)
- Integração com Supabase (cada tabela isolada por obra_id)
- UI responsiva com tabs, modais, tabelas
- Stub funcional (CRUD básico, sem cálculos avançados ainda)
- 4 novos botões na home (📊 EAP, 📅 Planejamento, 💳 Financeiro, 📦 Suprimentos)

**Testado:** Isolamento ✅ (18 arquivos, sem vínculos), Sintaxe ✅ (31 blocos), Testes (2 falhas pré-existentes do supabase-config)

**Próximas etapas:** Criar migrations no Supabase para as 4 tabelas, implementar cálculos (EVM, gráficos Gantt, fluxo de aprovação automático).
