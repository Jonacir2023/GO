2. Mas `mudarSubAbas()` usava seletor `[id^="riscos-"][id$="-aba"]` que casava TAMBÉM com a div principal `riscos-aba`
3. Isso fazia com que `mudarSubAbas()` ocultasse a div pai ao mostrar o filho, deixando tudo invisível

**Solução aplicada:**
- Removida função `mudarSubAbas()` duplicada (estava definida duas vezes)
- Alterado seletor de `[id^="riscos-"][id$="-aba"]` para `#riscos-registro-aba, #riscos-acoes-aba, #riscos-cobertura-aba, #riscos-priorizacao-aba`
- Adicionada verificação defensiva em `mudarAba()`: `if (event && event.target)` para evitar erro ao chamar via JS direto

## Correção: Suporte a Date objects na conversão de datas (EAP/Cronogramas)

**Problema:** Ao importar arquivo EAP em Excel (.xlsx), o sistema rejeitava TODAS as datas com erro "Datas inválidas (use DD/MM/YYYY)", mesmo que o arquivo estivesse no formato correto.

**Causa raiz:** 
- SheetJS (via openpyxl) retorna datas do Excel como:
  1. Python datetime objects (quando lendo com openpyxl)
  2. Excel serial numbers (em alguns contextos)
- A função `converterData()` só aceitava strings no formato DD/MM/YYYY ou YYYY-MM-DD
- Faltava validação de mês (1-12) e dia (1-31)

**Solução:**
- Atualizar `converterData()` para lidar com:
  1. Date objects → converter para YYYY-MM-DD direto
  2. Excel serial numbers → converter para Data JS → YYYY-MM-DD
  3. Strings → regex + validação como antes
- Adicionar validação explícita de mês (1-12) e dia (1-31)
- Melhorar check de data válida: comparar ano/mês/dia completos, não só getDate()

**Resultado:** Importação de EAP agora funciona com arquivos Excel que têm datas como Date objects. O arquivo EAP_F1.xlsx (novo formato da Cesbe) agora importa sem erros.

**Testes:** ✓ test_planejamento_atividades.py passou
